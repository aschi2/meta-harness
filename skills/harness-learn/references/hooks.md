# Hook registration

Set `"hooks": true` in a generation plan to register the shared PreToolUse and Stop entry point for its selected targets. Target names are `claude-code` and `codex`; profiles without a targets field register both. Existing settings require an explicitly adopted plan entry. The resulting settings are managed files in the checks and loop parts.

Claude Code project settings use `.claude/settings.json`. Codex supports project `.codex/hooks.json`; Codex loads that project layer only after the workspace is trusted. Sources checked 2026-11-03: [Claude Code hooks](https://code.claude.com/docs/en/hooks), [Codex hooks](https://learn.chatgpt.com/docs/hooks).

`meta-harness overlay install --dry-run` previews user-level registration. Installation follows settings symlinks, saves backups and an undo journal, and preserves unrelated hooks. `--overlay <directory>` records that override only in user settings. Project registration never records a personal overlay path.

Codex approval uses the app-server `hooks/list` and `config/batchWrite` RPCs, matching the added command, event, matcher, timeout and source path. If Codex is unavailable or an entry cannot be matched unambiguously, installation prints instructions to review it in `/hooks`.

The registered command invokes Bun by its absolute executable path with `--no-env-file` and an absolute, empty `hook.bunfig.toml` selected with `--config=...`. Bun documents that `--no-env-file` disables automatic `.env` loading and `--config` selects a specific Bun configuration file instead of the startup directory's `bunfig.toml`; this prevents a repository's dotenv values and preload scripts from changing the user-level hook runtime. The hook uses the event's `cwd` as the repository path. The rule worker has a 5 second default deadline for PreToolUse and a 60 second default for Stop; `--timeout-ms` or `META_HARNESS_HOOK_TIMEOUT_MS` can adjust it. A timed-out worker is killed and the hook fails open.

Sources checked 2026-11-03: [Bun environment variables](https://bun.sh/docs/runtime/environment-variables), [Bun CLI](https://bun.sh/docs/runtime), [Bun configuration](https://bun.sh/docs/runtime/bunfig), [Bun standalone executable options](https://bun.sh/docs/bundler/executables). A compiled hook executable must set `compile.autoloadDotenv: false` and `compile.autoloadBunfig: false` (or pass `--no-compile-autoload-dotenv` and `--no-compile-autoload-bunfig` to `bun build --compile`). These compile-only flags are distinct from runtime `--no-env-file` and `--config`.

On Windows, the registered Claude handler explicitly selects `shell: "powershell"`; Claude's current docs list Bash/Git Bash as the default with PowerShell as the fallback, and support this handler-level shell setting. Codex command hooks run through PowerShell on Windows. The generated command uses PowerShell's `&` call operator and single-quoted arguments there. Sources checked 2026-11-03: [Claude Code hooks](https://code.claude.com/docs/en/hooks), [Codex hooks](https://learn.chatgpt.com/docs/hooks).

Stop runs the Codex instruction budget only when the harness targets Codex or the user overlay opts in with `preferences.instructionBudget: true`. It measures the Codex global file selected from `CODEX_HOME` (default `~/.codex`): `AGENTS.override.md` when present, otherwise `AGENTS.md`, followed by the `AGENTS.md` chain from the Git root to the event's `cwd`. The budget blocks only after one of those files changed. A Claude-only harness does not get Codex's limit. See the [Codex instruction files documentation](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Local rule approval is stored outside the repository in the user config's `rule-trust.json`, keyed by the repository real path and each rule file's hash. Approve current files with `meta-harness approve --rules --target <repo>`; changed or unapproved files are skipped with a diagnostic until approved again. Repository rule files cannot approve themselves.

The user-level install journal records only entries it added and is written with mode `0600`; settings backups retain the original file mode. Uninstall removes its backup files after it verifies and completes an exact reversal. It retains Codex's historical `hooks.state` trust hashes; there is no active hook after its registration is removed. The installer does not issue an undocumented inverse RPC to erase that history.
