# Wiki checker contract

YAML distinguishes mappings, sequences, and scalars. The checker uses Bun's built-in YAML parser and accepts only a mapping as frontmatter. (https://yaml.org/spec/1.2.2/, published 2021-10-01, reviewed 2026-11-03; https://bun.sh/docs/runtime/yaml, accessed 2026-11-03)

Git's porcelain v1 `-z` output uses NUL separators, root-relative unquoted paths, and destination-then-origin fields for renames. The checker consumes that format without opening source files or reading diffs. (https://git-scm.com/docs/git-status, accessed 2026-11-03)

CommonMark defines inline and reference links, code spans, and fenced code blocks. The CommonMark reference parser (`commonmark` 0.31.2) supplies real link and heading nodes, excluding HTML comments and both fenced and indented code. Obsidian wikilinks are an additional syntax recognized only in parsed text nodes. (https://spec.commonmark.org/0.31.2/, published 2024-01-28, reviewed 2026-11-03)

The remaining decisions are pack policy / heuristics, set 2026-11-03:

- Run with `bun /path/to/pack/checkers/wiki-lint.ts [target]`, or invoke `[process.execPath, checkerPath]` from Bun. Default target is the current working directory. The export is `wikiLint(target): Promise<{rule, path}[]>`. CLI output is JSON `{counts, findings}` and exit 1 means findings. No page text, raw content, absolute paths, or parser error details appear in output.
- `frontmatter`: every non-excluded `wiki/**/*.md` needs syntactically valid YAML mapping frontmatter, including index and log. A leading UTF-8 BOM is stripped; indentation is preserved for CommonMark parsing. When `type` or `kind` is supplied, its value must be exactly one of `index`, `log`, `overview`, `source`, `analysis`, `entity`, `concept`, or `topic`. Unknown or capitalized values produce `page-type`. Required domain fields belong in the generated AGENTS schema document; `{}` is a valid mapping. A URL alone never proves local provenance.
- `raw-reference`: pages in `source/`, `sources/`, `analysis/`, or `analyses/`, or with `type`/`kind` equal to `source`/`analysis`, need at least one existing regular file under `raw/`. Accepted frontmatter fields are `sources`, `source`, and `raw`: strings, lists, or nested `files`/`file`/`path` records. Markdown raw links count too. The checker uses metadata, not contents.
- `index-link`: require `wiki/index.md`; every supported local link in it must resolve to a regular file. `raw/` and `wiki/` prefixes resolve from the target root, other links from the containing page. Fragments are ignored for file existence. HTTP(S) and mailto links are not fetched. Inline, angle-delimited and reference-style CommonMark links are supported. `[[name]]`, `[[name|alias]]` and `[[name#heading]]` use unique basenames across non-excluded regular files in the harness; ambiguous basenames produce `ambiguous-link`. Explicit paths resolve locally or from `raw/` / `wiki/`; `.md` is tried when needed. Comments and code never provide links. HTML links, embedded images as navigation, and advanced renderer-specific syntax are outside the contract.
- `orphan-page`: traverse page links from the index, including links across source and analysis pages. Every parsed page must be reachable, except index and log. A disconnected cycle is still orphaned. An invalid-frontmatter page is reported under `frontmatter` instead, but its body links still participate in reachability so a metadata failure does not make other pages appear orphaned.
- `log-order`: require `wiki/log.md`. Each level 2–6 entry heading begins with a real ISO calendar date, optionally bracketed. Entries are newest first; equal dates are allowed. Bullets and prose under a heading are continuation text and need no dates. An empty initial log is valid.
- `raw-immutable`: additions are allowed, but modifications/deletions of sources present in HEAD fail, including staged or unstaged changes. Renaming an existing source is a deletion and fails. In a Git repo without commits, all raw files are additions. `skip-worktree` and `assume-unchanged` raw index entries fail even if Git status hides their changes. Ignored, untracked raw files have no Git baseline and changes to them cannot be detected; do not ignore `raw/` if this protection is required, or use Git LFS for owner-approved large sources. ([Git diff](https://git-scm.com/docs/git-diff), [Git update-index](https://git-scm.com/docs/git-update-index), [Git LFS](https://git-lfs.com/), accessed 2026-11-03.) A non-Git target has no immutability result; Git failures in a detected repo fail closed at `raw`.

- `unsafe-path`: do not follow page or raw-reference symlinks, including directory symlinks. Reject absolute paths, escaping links, unsupported URI schemes, and references outside `wiki/` or `raw/`. Never read `.env*`, `.git/`, `.harness/`, `receipts/`, `tmp/`, or nested wiki `raw/` directories. Excluded paths are not wiki pages. Diagnostics identify the referring page, not an escaping destination. The checker assumes the local filesystem is not concurrently swapped by an adversarial writer.

Existence and graph checks do not establish claim truth, freshness, citation quality, or semantic consistency. Those require evidence-based review.

Instructions use `managed` mode: drift is reported and update merges it. Wiki pages, index and log use `seed` mode and remain workflow-owned after init. `profile.json` uses `owner` mode, is declared in pack ownerPaths, and requires `meta-harness approve profile.json` after an owner edit. Maintenance cannot change owner paths.
